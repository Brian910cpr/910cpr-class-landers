## Backend work performed while production gates remain open

Added `supabase/functions/canonical-session-workspace/payment-summary.ts` as a pure, deliberately unwired projection. It accepts explicitly registration-linked native-order evidence, deduplicates identical rows, rejects conflicting duplicate evidence, refuses to select a favorable order from multiple orders, distinguishes paid/refunded, and preserves unknown for held/open/expired/cancelled orders. It does not infer due from an incomplete checkout. Stripe is named only when a Stripe source identifier exists; otherwise source remains LanderWare. Its returned object contains only provider, status, evidence class and reason; amounts, IDs, URLs, payer details and recovery tokens are excluded.

This advances native canonical evidence reuse rather than adding an Enrollware dependency or a competing catalog. It preserves the mature order-versus-participant distinction and never equates registered with paid. It does not resolve organization payer identity; that remains a separate proven relationship requirement.
