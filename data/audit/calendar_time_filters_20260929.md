## Behavior and constraint contract

`docs/assets/calendar-time-filters.js` exports `compile`, `parseSmart`, `filterDates`, `mount`, and `BUCKETS` using the project's browser/CommonJS pattern. `docs/assets/calendar-time-filters.css` supplies compact responsive styles.

`compile(bucketIds, text, businessDate)` returns:

```json
{
  "valid": true,
  "active": true,
  "timeRanges": [{"min": 360, "max": 720}],
  "include": [{"daysOfWeek": [1, 2, 3, 4, 5], "startTimeMin": null, "startTimeMax": 600, "dateMin": null, "dateMax": null}],
  "exclude": [],
  "summary": "...",
  "error": ""
}
```

- Checkbox ranges use start-inclusive, end-exclusive minute boundaries: `[0,360)`, `[360,720)`, `[720,1020)`, `[1020,1260)`, `[1260,1440)`. Each start belongs to exactly one bucket.
- Selected checkboxes are ORed; their union is ANDed with Smart include/exclude constraints.
- Every page first calls existing `filterDatesByCourse(scheduleDates, activeCourseIds())`; only that result enters the timing filter. Dates/slots can only be removed; course objects and registration targets remain intact.
- Smart parsing is local and deterministic; text does not leave the browser. It supports all seven requested examples, weekday lists, weekend/weekday groups, named periods, explicit AM/PM or 24-hour bounds, ranges, ISO dates, today/tomorrow/this week/next week, explicit alternatives, and exclusions such as `can't Tuesday evening` or `after 6pm except Tuesday`.
- `after` and `before` are strict; `at or after` / `at or before` allow inclusive bounds. Morning means 6 AM-noon. After work means after 5 PM, disclosed in the interpretation. Next week means next Monday-Sunday based on `businessNow()` in America/New_York.
- Invalid/unsupported wording fails closed with a readable example and zero matches. Unknown restrictions are never silently discarded. This is a scheduling grammar, not an unrestricted language model.
- Exclusions match **start times**, as requested. They do not promise that an entire course duration avoids a personal conflict; the UI says it matches class start times.
- With timing filters active, no-results suppresses the existing alternative-course prompt. Clear removes only the new constraints, preserving selected course/family/compare state.
- Assets use `?v=20260929.1`; the mounted control exposes `data-version="20260929.1"`.
